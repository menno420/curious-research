## ⚠️ CORRECTION — the ranked findings above assumed the wrong usage model

Recorded after the owner corrected the premise. The review above was written
assuming the recipient browses the repo on github.com and/or clones it to his
own laptop. **Neither is the intended model.** The owner's actual intent: the
recipient opens **Claude Code on the web** (claude.ai/code), which clones this
repo into an ephemeral cloud container — the same environment this session ran
in — and Claude explains and works on it with him there. The owner's stated
goal is explicitly pedagogical: *"make this in such a way that he understands
the value of GitHub and how easy it is to work with it with Claude."*

**Three findings from the review are WRONG under the real model and are hereby
retracted.** Do not act on them:

1. ~~Hooks fail on his machine (`/usr/local/bin/python3` hardcoded)~~ —
   **retracted.** Verified in-container: that path exists (symlink to
   `/usr/bin/python3.11`, created at provisioning) and all four hooks fired
   correctly this session. The hardcoded interpreter is right for this
   environment.
2. ~~The `git reset --hard origin/main` preflight destroys his work~~ —
   **retracted.** Verified: `.git` was created 07:06:09, minutes before the
   session. The clone is ephemeral and freshly made, so the hard reset is
   correct hygiene, not a footgun.
3. ~~The PR loop is a mechanic he can never perform~~ — **retracted, and
   inverted.** Because the container is reclaimed after inactivity, commit +
   push is the *only* way anything survives. The PR loop is load-bearing, and
   the substrate machinery (session cards, gate, auto-merge) is what makes the
   repo remember him across containers. Earlier "76 % machinery is dead weight"
   framing was wrong: the kit earns its keep. Only `control/` (inbox/outbox/
   ORDER protocol addressed to a manager seat that no longer exists) is genuine
   dead weight in this model.

## 💡 Session idea

The repo's highest-friction moment is that the recipient must know what to ask
before it does anything. An **issue-template front door** inverts that: he
clicks *New issue*, types "why does my PETG string so much", and an agent
answers by shipping a new animated guide and closing the issue with the link.
That needs no git literacy, no clone, no local tooling — and it converts the
repo from a book he reads into the companion the README already claims it is.
It also gives the dormant seat a legitimate wake signal that is driven by his
actual curiosity rather than by a cron tick manufacturing busywork.
