## 💡 Session idea

The repo's highest-friction moment is that the recipient must know what to ask
before it does anything. An **issue-template front door** inverts that: he
clicks *New issue*, types "why does my PETG string so much", and an agent
answers by shipping a new animated guide and closing the issue with the link.
That needs no git literacy, no clone, no local tooling — and it converts the
repo from a book he reads into the companion the README already claims it is.
It also gives the dormant seat a legitimate wake signal that is driven by his
actual curiosity rather than by a cron tick manufacturing busywork.

## ⟲ Previous-session review

The previous session (`2026-07-14-current-state-refresh.md`, the seat-dormant
handoff) closed the seat cleanly and left an honest, well-cited trail — the
dormancy record in `control/status.md` names the deleted triggers by ID and

Its one gap is audience drift, and it is the root of finding #3: the close-out
wrote its handover *for the next agent* and then linked that same file from
`README.md` as the owner's pick-up guide. **Workflow improvement:** any
artifact linked from `README.md` must pass an owner-audience read — if it
contains kit or fleet vocabulary (EAP, seat, ORDER, PROPOSAL, ruleset), it
belongs under `docs/` unlinked from the front page, and the README gets a
plain-language equivalent instead. Guard recipe for a later session: the check
that would catch this is a README-link audience lint — walk the link targets in
`README.md`, flag any whose body matches the fleet-vocabulary set, anchor it
next to the existing link walker so it shares the same target-resolution code.
